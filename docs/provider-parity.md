# Provider parity evidence

The reference implementation is the preserved Python repository at commit
`3b0f5a92ddea26313338eb52cfe4c5dc19ed5852`. Fixtures in `test/fixtures/`
were generated by invoking its real normalization and tool functions with
injected HTTP replies and fixed clocks. No real provider mutations were made.

| Area | Complete tool-response fixtures | Compared behavior |
| --- | ---: | --- |
| Gmail | 30 | Read/search/thread output, MIME alternatives and budgets, folded/encoded headers, pagination, send/reply preflight, receipt validation and uncertain outcomes |
| Calendar | 22 | Discovery and scan limits, partial coverage, selection ambiguity, all-day zones, UTC ordering across DST, timestamp precision, conflicts and mutation reservation order |
| Maps place search | 8 | Missing/ambiguous area, precision, fallback geocoding, pagination and candidate validation |
| Maps place details | 18 | Opening-hours presence/null distinctions, proto zeroes, calendar dates, bounds, phone normalization and API-key redaction |
| Maps walking routes | 23 | Complete steps, sanitized instructions, geometry validation, compass bearings, elevation/step coverage, degradation and output budgets |
| Windguru | 25 | Native units, source fields, optional model metadata, selected set order, compact columns, partial failures and malformed selected/unselected records |

These tests compare complete result JSON, including explicit nulls, omissions,
ordering, counts and error codes. They also check request counts and Calendar
reservation counts. HTTP mocks match provider resources and relevant query
parameters. Maps search comparisons remove only randomly generated `ref` values.

Separate Windguru tests verify that cached responses retain their original
retrieval timestamp, completed forecasts survive a shared deadline, and saved-set
memory lookup consumes that same deadline. The shared cache test checks bounded
call-local LRU behavior. The complete corpus also retains pure reference fixtures
for contacts (5 cases), Gmail bodies (6), Gmail summaries (3), compass headings
(16), elevation filtering (6), note completion phrases (6), and quote selection
(5). `MailContentSpec` additionally exercises standard codec boundaries and
concurrent converter independence.

Run the normal suite with `stack test`. Provider tests use injected capabilities;
HTTP request construction, JSON derivation, MIME encoding, text decoding and
normalization execute in Haskell. Production does not call the Python reference.

## Limits of this evidence

- These fixtures cover the recorded cases; they are not an exhaustive proof for
  every possible malformed or future provider payload.
- Outbound Gmail tests compare semantic results and preflight/receipt behavior.
  They do not require MIME bytes, generated message identifiers or header folding
  to be byte-for-byte identical across the two standard MIME implementations.
- Live OAuth refresh, current remote API behavior, actual email/attachment
  delivery and calendar invitations need authorized live verification. The
  fixture suite does not establish that these side effects occurred.
- Telephony, durable storage, and deployment evidence are recorded by their own
  suites and migration documentation. Provider fixtures do not establish that a
  complete live call has been exercised.
